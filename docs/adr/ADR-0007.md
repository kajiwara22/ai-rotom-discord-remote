# ADR-0007: 対戦環境・メタ情報の取り込みは見送り、ai-rotom の収録データに基づく助言に限定する

## ステータス

見送り

> 外部検索（案B）と保護者による環境メモ（案C）を検討したが、**いずれも導入しない**
> 判断とした。同じ議論を繰り返さないよう、検討の経緯と再検討の条件を残す。

## コンテキスト

### 状況 (Situation)

`@nonz250/ai-rotom` は静的なデータベースであり、次を持っている。

- 収録ポケモン 323 体（メガシンカ含む）の種族値・タイプ・特性・覚える技
- 技・持ち物・性格・タイプ相性・バトル条件のデータ
- ダメージ計算、素早さライン、対面分析、パーティ分析

[ADR-0006](./ADR-0006.md) の整形層により、これらの分析結果は LLM に正しく届くようになった。

### 課題 (Complication)

**このデータベースは「今どうなっているか」を持っていない。**

- どのポケモンがよく使われているか（使用率）
- 主流の型は何か（カバルドンは物理受けか、あくび搭載か、はらだいこ対策か）
- 環境の変化（アップデートによる調整、新規解禁）

結果として、AI は**理論上の最適解**しか出せない。「カバルドンの対策」に対し、
種族値と技から導ける答えは出せるが、「実際に当たるカバルドンは何をしてくるか」を
踏まえられない。

子どもがこの助言どおりに組んで負けたとき、AI が間違っていたのか環境が違ったのかを
本人が切り分けられない。これは対戦の勝利に貢献するという目的に対する構造的な穴である。

なお、ポケモンチャンピオンズは新しいタイトルであり、外部に蓄積された対戦情報の量と
質そのものが未知数である点にも注意が要る。

### 論点 (Question)

1. 外部の情報源を取り込むか
2. 取り込むなら、子どもが使うアプリとして何を通してよいか
3. 情報の鮮度と正確性をどう担保し、AI の回答の中でどう区別させるか

### 検討した選択肢 (Options)

- **案A: 取り込まない（理論値専用と割り切る）**
  - 概要: 現状維持。データベースにある事実だけで答える
  - メリット: 誤情報が混入しない。実装が不要
  - デメリット: 上記の穴が残る。「今流行っている型」を聞かれても答えられない

- **案B: Web 検索ツールを追加し、LLM に調べさせる**
  - 概要: 検索 API をツールとして追加し、必要に応じて LLM が呼ぶ
  - メリット: 情報が自動で新しくなる。手入力が要らない
  - デメリット:
    - **子どもが使うアプリに、フィルタされていないインターネットの情報が入る**。
      これは [ADR-0004](./ADR-0004.md) で PIN 保護を設けたのと同じ性質の判断であり、
      技術的な最適性だけでは決められない
    - 掲示板やまとめサイトの真偽不明な情報を、AI が事実として扱う危険がある
    - 新しいタイトルのため、そもそも信頼できる情報源が存在するか不明
    - 検索 API のコストと、応答時間の増加

- **案C: 保護者が「環境メモ」を書き、それを AI に渡す**
  - 概要: 保護者設定に環境メモ欄を設け、システムプロンプトへ実行時に付与する
    （[ADR-0003](./ADR-0003.md) のモード指示と同じ仕組み）
  - メリット:
    - 何を子どもに伝えるかを保護者が完全に制御できる
    - 実装が軽い（`system_prompts` と同じ構造をもう 1 つ足すだけ）
    - 情報源が人間なので、誤りがあっても責任の所在が明確
  - デメリット:
    - 保護者が書かなければ何も変わらない。更新が滞れば古い情報が残り続ける
    - 保護者自身が環境を知っている必要がある

- **案D: 対戦結果を記録し、自分たちの環境データを作る**
  - 概要: 「誰と当たって何をされたか」を蓄積し、AI に参照させる
  - メリット: 自分が実際に当たる相手の情報なので、使用率統計より実態に近い。
    子どもが自分で記録する行為自体に学習効果がある
  - デメリット: 記録の手間が大きく、続かない可能性が高い。母数が貯まるまで役に立たない

## 決定

### 案A を採り、環境情報は取り込まない

外部検索（案B）も保護者による環境メモ（案C）も導入しない。このアプリは
**ai-rotom に収録されたデータから導ける助言に限定する**。

案B を採らない理由:

- 子どもが使うアプリに、フィルタされていないインターネットの情報を通す判断になる。
  得られる利益に対してリスクの見積もりが難しい
- ポケモンチャンピオンズは新しいタイトルであり、信頼できる情報源が確立しているか
  自体が不明。精度の低い情報を「AI が言ったこと」として子どもに渡す危険がある

案C を採らない理由:

- 保護者の手入力に依存し、書かれなければ現状と変わらない。更新が滞れば古い情報が
  残り続けるが、**それに気づく仕組みがない**。誤った前提を与え続けるくらいなら、
  最初から持たないほうが安全である
- 保護者自身が環境を把握している必要があり、前提が成立しない期間が長い

### 結果として受け入れる制約

このアプリは「今の流行」に答えられない。使用率や主流の型を聞かれても、
データベースにない以上は答えられないままとする。

**理論値の助言は、それ自体で価値がある。** 種族値・タイプ相性・ダメージ計算・
素早さラインは環境が変わっても揺るがない事実であり、[ADR-0006](./ADR-0006.md) の
整形層によってこれらは正しく AI へ届くようになった。まずこの土台が実際に役立つか
どうかを見てから、足りないものを判断する。

### 再検討する条件

次のいずれかが起きたら、本 ADR を差し替える新しい ADR を起こす。

- 使ってみて「流行が分からないせいで助言が外れる」場面が繰り返し観測された
- ポケモンチャンピオンズの対戦情報について、信頼できる情報源が確立した
- 上流の `@nonz250/ai-rotom` が使用率などの情報を持つようになった

## 影響

### メリット

- 誤情報が混入する経路を持たない。AI の回答の根拠が常にツールの出力に辿れる
- 実装・運用のコストがゼロ。保守すべきものが増えない
- 子ども向けアプリとしての安全性の議論を、必要になるまで先送りできる

### デメリット・トレードオフ

- **「今どんな型が多いか」に答えられない。** 理論上の最適解と実戦で当たる相手の
  ズレは埋まらないままになる
- 子どもが助言どおりに組んで負けたとき、原因の切り分けができない
- 環境が動いても、このアプリの回答は変わらない

### 今後チームが意識すべきこと

1. **「便利だから」で外部検索を後から足さないこと**。本 ADR を差し替える ADR を
   起こしてから実装する
2. AI が流行や使用率を推測で語っていないか注意する。データベースにない以上、
   それは根拠のない発言である
3. 上記「再検討する条件」に当てはまる状況が観測されたら記録する
