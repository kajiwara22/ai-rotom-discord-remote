# ADR-0005: Web UI を「AIバトルコーチ」として全面刷新し、MVP.css を廃して自前 CSS に一本化する

## ステータス

採用

## コンテキスト

### 状況 (Situation)

[ADR-0001](./ADR-0001.md) に基づく初期 Web UI は、classless CSS の MVP.css と
最小限の vanilla JS で実装され、機能的には動作していた。
アプリ名は「ロトム図鑑」、AI の応答は Markdown を `marked` で描画していた。

### 課題 (Complication)

実利用者である小 1・小 5 の娘に使わせる前提で見直すと、複数の問題が同時に見つかった。

1. **レイアウトが崩れていた** — MVP.css の `header, main { margin: 0 auto;
   max-width: 1080px; padding: 3rem 1rem }` が自前の flex レイアウトに勝ち、
   全画面チャットのはずが中央の狭い箱に収まっていた。入力欄とチャット欄の左右もずれていた
2. **モバイルで実用に耐えなかった** — 390px 幅でサイドバーが画面の半分を占め、
   送信ボタンが画面外に出ていた
3. **子ども向けの作りではなかった** — 発言者をラベルだけで区別、待機表示は文字のみ、
   空状態は真っ白で何を聞けばよいか分からない
4. **`prompt()` / `alert()` を多用** — モバイルで体験が悪く、リネームは発見不能な
   dblclick だった
5. **表示が実態と合っていなかった** — [ADR-0003](./ADR-0003.md) の表示モードを実装するには、
   MVP.css の classless 前提が邪魔だった。またセッション名は
   `{日付} - {本文}` 形式で、一覧の日時と二重表示になり値も食い違っていた
6. **名称が実態と合っていなかった** — 「ロトム図鑑」はゲーム・アニメの固有デバイス名で
   あり、かつ本アプリは一方的に引く「図鑑」ではなく相談して作戦を練るチャットだった

### 論点 (Question)

1. MVP.css を維持したまま調整するか、捨てて自前 CSS にするか
2. UI の作り替えの範囲をどこまでにするか
3. アプリ名をどうするか
4. AI 応答の Markdown 描画にセキュリティ上の手当てが要るか

### 検討した選択肢 (Options)

- **案1: MVP.css を維持し、上書き CSS で不具合を潰す**
  - メリット: 変更が小さい
  - デメリット: classless 前提と表示モードの class ベース切り替えが相性最悪。
    `max-width` や `padding` を打ち消す上書きが増え、かえって複雑になる

- **案2: MVP.css を廃し、自前 CSS に一本化する**
  - メリット: 表示モードのトークン切り替え（`:root[data-mode]`）が素直に書ける。
    レイアウトの主導権を取り戻せる。外部フレームワークへの依存が消える
  - デメリット: スタイルを一から書く必要がある（ただし規模は小さい）

- **アプリ名の案**（AI であることを含め、固有名詞を避ける方針で検討）
  - AIバトルコーチ / AIポケモン博士 / AIバトルアドバイザー / 作戦AI など
  - 「コーチ」は鍛えてくれる相手という役割が明確で、対戦アドバイスの実態に合う

## 決定

### MVP.css を廃止し、自前 CSS（`style.css`）に一本化する（案2）

ADR-0001 の「CSSフレームワーク: MVP.css を採用する」「MVP.css はリポジトリに
静的ファイルとして含める」という決定を、本 ADR で置き換える。
`mvp.css` は削除する。外部 CDN や npm への非依存という ADR-0001 の原則は維持し、
vanilla JS + 自前 CSS で実装する。

### UI を「ロトム図鑑」筐体をモチーフに全面刷新する

- レイアウト: `100dvh` + flex + `env(safe-area-inset-*)` で全画面に敷き詰め、
  モバイルではサイドバーをドロワー化する
- 発言者をアバター付きの吹き出しで表現する（AI 側＝ロトム、ユーザー側＝選択アバター）
- 表は横スクロールするコンテナで包み、狭い画面で本文を潰さない
- `prompt()` / `alert()` を廃し、自前ダイアログとトーストへ置き換える
- リネーム・削除は「…」メニューに集約する
- 入力を `textarea` 化し、自動リサイズと Shift+Enter 改行に対応する
- 空状態に質問例チップ、待機中に経過秒数とイラスト、各回答に読み上げ／コピーを置く
- エラーは履歴に混ぜず、再送信できる専用カードで表示する

### アプリ名を「AIバトルコーチ」に変更する

「ロトム図鑑」は固有デバイス名であり実態（相談型チャット）とも合わないため改名する。
選定条件は「AI であることが分かる」「相談相手だと分かる」「固有名詞を含まない」。

なお **AI の発言者名は「ロトム」を維持する**。子どもにとっての親しみやすさを優先し、
アプリ名とは別のキャラクター名として扱う。内部的にも元の MCP サーバが `ai-rotom` で
由来は一貫している。

### セッション名から日付プレフィックスを除去する

ADR-0001 の「自動作成時のセッション名は `{YYYY-MM-DD HH:mm} - {先頭30文字}` 形式」を
本 ADR で置き換える。名前は最初の発言（先頭 40 文字）のみとし、日時は一覧側で
`updated_at` から相対表示（「9分前」「きょう 13:20」）する。
名前側が作成時刻・一覧側が更新時刻で値が食い違い、二重に日付が並んで混乱を招いていた。

### AI 応答の Markdown 描画をサニタイズする

`marked` は生 HTML をそのまま通すため、変換前に `<` `>` を実体参照へ置換する。
AI 応答やツール結果に含まれる HTML が実行されないようにする（実際に
`<img onerror>` を含む応答で検証し、スクリプトが実行されないことを確認した）。

## 影響

### メリット

- レイアウト崩れとモバイル非対応という致命的な問題が解消する
- 表示モード（[ADR-0003](./ADR-0003.md)）を素直に実装できる CSS 基盤になる
- 名称が実態に合い、AI ツールであることが伝わる
- 外部フレームワークへの依存が完全に消える

### デメリット・トレードオフ

- スタイルの記述量が増える（`style.css` として集約）
- classless の手軽さは失うが、本アプリの規模ではデメリットにならない
- 「図鑑」筐体のモチーフは残るため、名称と見た目にわずかな不一致がある
  （デザインの世界観としては許容する）

### 今後チームが意識すべきこと

1. **外部 CSS フレームワークを再導入しないこと**。表示モードのトークン切り替えと
   相性が悪く、ADR-0001 の非依存原則にも反する
2. **AI 応答を `innerHTML` に流す箇所では必ずエスケープを通すこと**。
   `renderMarkdown()` を経由し、生の `marked.parse()` を直接使わない
3. **UI 文言は [ADR-0003](./ADR-0003.md) の語彙テーブル両方に追加する**
