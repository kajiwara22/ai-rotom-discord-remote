# ADR-0019: ai-rotom MCP サーバーの起動方式は環境変数で切り替え可能とする

## ステータス

採用

## コンテキスト

### 状況 (Situation)

rpi-bridge は ai-rotom MCP サーバーを stdio で起動して接続している
（`src/index.ts` の `StdioClientTransport`）。現在の起動は次の固定指定である。

```
command: "npx", args: ["-y", "@nonz250/ai-rotom"]
```

`npx -y` は npm の `latest` タグを解決するため、**常に最新リリース版**が使われる。
`package.json` の `@nonz250/ai-rotom` 依存は実質デッド（import はこの起動文字列のみ）。

### 課題 (Complication)

ai-rotom の次期版（main ブランチ）をリリース前に試したい場面がある。しかし
未リリース版を起動する手段がコード上に無く、`npx github:...` による git 直接起動も
成立しない。

- `dist/` は gitignore 済みで、git から取得しても実行バイナリが無い
- `prepare` / `prepack` / `postinstall` が無く、インストール時にビルドされない
- npm パッケージはモノレポの `packages/mcp-server` にあり、ルートは `private: true`
  で bin を持たない

したがって未リリース版を使うには、**ローカルでビルドした `dist/index.mjs` を `node`
で直接起動する**のが現実解となる。ビルドは Node ≥24 が必要（Pi は mise の Node 26
で充足）。ビルド後も `@modelcontextprotocol/sdk` と `zod` は外部依存として
node_modules に残るため、git チェックアウトと node_modules を保持する必要がある。

### 論点 (Question)

1. 「最新リリース版」と「ローカルビルドの main 版」を、コード変更なしで切り替えるには
   どうするか
2. 切り替えを導入しても、既存の運用（npx で latest に自動追随）を壊さないか

### 検討した選択肢 (Options)

- **案A: 環境変数でコマンド・引数を切り替える（採用）**
  - 概要: `AI_ROTOM_COMMAND` / `AI_ROTOM_ARGS` で起動方式を上書きできるようにする。
    既定は現行の `npx -y @nonz250/ai-rotom`。
  - メリット: コード変更なしで切り替えられる。既定値で現行挙動が完全に保たれる。
    設定は `.mise.local.toml` の `[env]` に書くだけ。
  - デメリット: 引数を空白区切りで渡すため、空白を含むパスは扱えない（Pi の実運用
    パスでは問題にならない）。

- **案B: `node <固定パス>` に直書きする**
  - 概要: transport 生成部をローカルビルドのパスへ書き換える。
  - メリット: 変更が最小。
  - デメリット: 環境依存のパスがコードに入る。リリース版へ戻すのに再編集が必要。
    却下。

- **案C: package.json を git 依存に差し替える**
  - 概要: `@nonz250/ai-rotom` を git URL 依存にする。
  - メリット: 依存管理に乗せられる。
  - デメリット: dist 未ビルド・prepare 無し・モノレポサブディレクトリのため、
    git 依存のインストールだけでは動かない（別途ビルド手順が必要）。却下。

## 決定

### 起動方式は環境変数 `AI_ROTOM_COMMAND` / `AI_ROTOM_ARGS` で切り替える（案A）

- `AI_ROTOM_COMMAND`: 既定 `npx`
- `AI_ROTOM_ARGS`: 既定 `-y @nonz250/ai-rotom`（空白区切りで分割）
- 未リリース main を使う場合は、ローカルビルド先を指して
  `AI_ROTOM_COMMAND=node`、
  `AI_ROTOM_ARGS=/path/to/ai-rotom/packages/mcp-server/dist/index.mjs` を設定する
- 起動時に解決後のコマンドをログへ出し、どの版で動いているかを確認できるようにする

### 既定値は現行の npx のまま

既定値を変えないことで、環境変数を設定しない既存運用（リリース版追随）は何も
変わらない。切り替えは明示的に環境変数を設定したときだけ有効になる。

## 影響

### メリット

- リリース版 ↔ main 版を、`.mise.local.toml` の `[env]` 変更だけで行き来できる。
- 既定値が現行のため、未設定時は従来どおり latest へ自動追随する（導入で運用が
  変わらない）。
- 起動ログで実際の起動方式を確認でき、意図と違う版で動かす事故を防げる。

### デメリット・トレードオフ

- `AI_ROTOM_ARGS` は空白区切り分割のため、空白を含むパスは渡せない（Pi の実運用では
  問題なし。必要になったら JSON 配列などに拡張する）。
- 未リリース版の更新は自動ではなく、`git pull && npm run build` → ブリッジ再起動が
  必要。これは自動追随を止めて制御するという意図であり、トレードオフとして受け入れる。

### 今後チームが意識すべきこと

1. **既定の `npx` は常に latest を解決する**。`AI_ROTOM_*` を設定しない限り、
   リリース版へ自動追随する点は従来どおり。
2. **main 版への切り替えは検証目的の一時運用を想定する**。恒久的に main を追う
   運用に移す場合は、ビルド・更新手順の自動化を別途検討する。
3. **main 版はローカルビルドが前提**（dist は gitignore、prepare 無し）。Pi 上に
   git チェックアウトと node_modules を保持する必要がある。
4. 起動方式を変えたら、起動ログの `[ai-rotom] 起動方式:` を確認する。
