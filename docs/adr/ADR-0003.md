# ADR-0003: 年齢差への対応は「表示モード」をユーザー属性として持ち、UI と AI 応答の両方を切り替える

## ステータス

採用

## コンテキスト

### 状況 (Situation)

[ADR-0001](./ADR-0001.md) に基づき、家庭用 Web チャット UI を Raspberry Pi 上に実装した。
利用者は父と小学生の娘 2 人（小 1・小 5）である。

ADR-0001 では「ユーザーごとのシステムプロンプト調整」により年齢差へ対応する想定だったが、
これは AI の応答スタイルにしか効かず、UI 自体は全ユーザー共通だった。

### 課題 (Complication)

初期実装の UI を小 1 に合わせて作ったところ、小 5 には「幼すぎる」という評価となった。
一方で小 1 には漢字中心の UI は読めない。次が同時に必要になった。

- 語彙: 「あたらしい おはなし」か「新しいチャット」か
- 文字サイズ・情報密度: 大きく余白多めか、小さく一覧性重視か
- 装飾: ぽってりした角丸・押し込み感か、フラットでシャープか
- **AI の回答の難易度**: ひらがな中心の短文か、種族値や SP 調整の数値を含む説明か

UI だけを大人向けにしても、回答が幼いままでは小 5 の不満は解消しない。

### 論点 (Question)

1. 年齢差をどの単位で保持するか（ユーザー属性か、その場のトグルか）
2. 切り替えの対象を UI に限るか、AI 応答まで含めるか
3. 誰が切り替えられるか

### 検討した選択肢 (Options)

- **案1: 文字サイズだけを切り替える**
  - 概要: 既存の「文字サイズ」設定のみで対応する
  - メリット: 実装が最小
  - デメリット: 語彙（ひらがな/漢字）が変わらず、幼い印象の主因を解消できない

- **案2: 画面上のトグルで誰でも即座に切り替える**
  - 概要: ヘッダー等に「こども/おとな」トグルを置く
  - メリット: 実装が単純、切り替えが手軽
  - デメリット: 子どもが面白がって頻繁に切り替える。設定が安定せず、
    「自分向けの画面」という感覚が育たない

- **案3: 表示モードをユーザー属性として DB に持ち、UI と AI 応答の両方を切り替える**
  - 概要: `users.mode`（`kids` / `junior`）を追加し、ユーザー選択に追随させる
  - メリット: 一人ひとりに固定の体験を与えられる。回答の難易度まで一致する
  - デメリット: カラム追加とマイグレーションが必要。語彙テーブルの二重管理が発生する

- **案4: 年齢（数値）を持ち、閾値で自動判定する**
  - 概要: `users.age` を持ち、システム側で段階を決める
  - メリット: 属性として自然
  - デメリット: 誕生日で挙動が勝手に変わる。実際に必要なのは 2 段階のみで過剰

## 決定

### 案3 を採用し、表示モードをユーザー属性とする

`users` テーブルに `mode` カラム（`kids` / `junior`、既定 `kids`）を追加する。
ユーザーを切り替えると、そのユーザーのモードが UI 全体に適用される。

| | kids（小 1 想定） | junior（小 5〜大人想定） |
|---|---|---|
| 語彙 | あたらしい おはなし／けす | 新しいチャット／削除 |
| 本文サイズ | 19px | 16px |
| 角丸・枠線 | 18px・2px | 12px・1px |
| 履歴の行 | 2 行折り返し | 1 行省略 |
| 待機表示 | イラスト＋「ロトムが しらべているよ！」 | 回転アイコン＋控えめな表示 |
| フォント | 丸ゴシック | ゴシック |

CSS は `:root[data-mode="junior"]` によるトークン上書きで切り替え、
文言は JavaScript の語彙テーブル（`L.kids` / `L.junior`）で切り替える。

### AI 応答の難易度もモードで切り替える

UI の見た目だけでは不十分なため、システムプロンプトへモード別の指示を
**実行時に付与**する（`conversation-manager.ts` の `MODE_INSTRUCTIONS`）。

- kids: ひらがな多め、短文、専門用語は言い換える、200 文字程度まで
- junior: 漢字通常、対戦用語をそのまま使う、種族値・SP 調整など具体的な数値を示す

### モードの変更は保護者のみが行える

子どもが気軽に切り替えるものではなく、一人ひとりに固定して与える設定と位置づける。
変更は保護者設定（PIN 保護、[ADR-0004](./ADR-0004.md)）からのみ行う。

一方、文字サイズは独立した設定として子ども自身が変更できる場所に残す。
モードによる基準値に上乗せする形で働く。

### モード指示は保存内容へ焼き込まない

システムプロンプトの取得を編集用（`getStoredSystemPrompt()`）と
実行用（`getSystemPromptForUser()`）に分離する。

編集画面へモード指示を含めて返すと、保存のたびに指示が本文へ蓄積して増殖する。
実装時に実際にこの不具合を作り込んだため、明示的に分離した。

## 影響

### メリット

- 小 1 と小 5 が同じアプリを、それぞれに合った形で使える
- 回答の難易度まで一致するため、「子ども扱いされている」感覚を与えない
- ユーザー切り替えだけで体験が切り替わり、子どもが設定を意識しなくてよい

### デメリット・トレードオフ

- 語彙テーブル（`L.kids` / `L.junior`）の二重管理が発生する。
  UI 文言を追加するときは必ず両方に定義が必要
- モードを増やす場合（例: 未就学児向け）は語彙テーブルとスタイルの両方に追加が要る
- AI 応答はモデルの裁量に依存するため、指示どおりの難易度になる保証はない

### 今後チームが意識すべきこと

1. **UI 文言の追加時は `L.kids` と `L.junior` の両方に定義する**。片方だけだと
   そのモードで文言が空になる
2. **モードを UI 限定の設定に「単純化」しないこと**。AI 応答への注入が本質であり、
   これを外すと年齢差対応の効果が半減する
3. **`getStoredSystemPrompt()` と `getSystemPromptForUser()` を混同しないこと**。
   編集系 API は必ず前者を使う
